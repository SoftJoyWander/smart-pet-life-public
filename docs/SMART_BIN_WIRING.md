# 智能垃圾桶 第一階段接線表

協定與產品設計見 [SMART_BIN_DESIGN.md](./SMART_BIN_DESIGN.md)。本文件只處理**硬體怎麼接**。

狀態：**模擬電路已全部在實體上驗證通過**（2026-09-14）——
韌體、腳位、回饋輸入、開鎖輸出四者串成完整迴路，按下按鈕會驅動「鎖」。
**12V 與真鎖的部分仍為紙上設計，尚未驗證。**

## 這一階段做什麼

只做核心迴路：**手機下指令 → 鎖打開 → 裝置能確認鎖真的動了**。

不做：外殼、出袋機構、滿載偵測、電池供電。這些都等核心迴路跑通再說。

「能確認鎖真的動了」是重點。沒有回饋訊號的話，韌體只知道自己輸出了開鎖訊號，不知道鎖有沒有動——那份回執就不能被後端信任，整個安全模型會空掉。所以這一階段一定要把四線鎖的回饋接點接起來。

## 工作順序（跟到貨順序不一樣）

下面的「步驟一到六」是**接線時的依賴順序**——不知道哪兩條是線圈就不能接鎖，所以線序辨識排在最前面。但接線是第一階段的**最後一段工作**，不是最先。

零件分三家出貨，到貨時間不同。電磁鎖預期最晚到，而它**只影響最後 20% 的工作**。前面的都可以先做：

### 只要 ESP32 + 麵包板 + 杜邦線

不需要電錶，也不需要 12V 的任何東西。

- 裝開發環境、燒 blink、確認序列埠有輸出
- **對照實物確認 C3 核心板實際引出哪些 GPIO**（這直接解決「尚未驗證」的第三項）
- 用套裝裡的按鈕接 GPIO5，驗證 `INPUT_PULLUP` 讀值（按下 `LOW`、放開 `HIGH`）
- 用 LED 接 GPIO4 串 220Ω，代替鎖
- **整個 BLE GATT 契約**：服務與特徵值、挑戰／回應、HMAC-SHA256、計數器防重放。這一大塊完全不碰 12V

### 用 LED 和按鈕模擬鎖

這是重點：**鎖在電路上只是一個「通電會動的東西」加一個「會開合的接點」**。

- LED（GPIO4）代替線圈：亮 = 通電
- 按鈕（GPIO5）代替回饋接點：按下 = 鎖舌縮回

有這兩樣，狀態機、逾時、`lock_failed` 錯誤路徑、事件與回執的產生，全部都能寫完並測完。等真鎖到貨，把 LED 換成 MOS、把按鈕換成回饋線就好，韌體一行都不用改。

反過來說也成立：**如果沒先用模擬跑通，真鎖接上去出問題時，你分不清是韌體錯還是接線錯。** 先讓軟體那一半確定是對的。

### 電錶到了可以做

- 驗證電錶本身正常（通斷檔兩支表棒對碰，應該嗶）
- **步驟二**：MOS 模組端子辨識（只需要 MOS + 電錶）
- **步驟五第 2 項**：變壓器極性（變壓器 + DC 母頭 + 電錶）

### 只有鎖到了才能做

- **步驟一**：四線線序辨識
- **步驟六** A／B／C 三段上電

## 動手前：工具怎麼用

這一節是給第一次接電路的人看的。已經熟的可以跳過。

### 麵包板：哪些孔是相連的

麵包板不用焊接，靠孔內的金屬夾片把零件腳夾住並互相連接。**關鍵是知道哪些孔本來就通在一起** —— 這決定了東西要插在哪。

```
          ┌───────────────────────────────────────────┐
    ＋ →  │ ○ ○ ○ ○ ○   ○ ○ ○ ○ ○   ○ ○ ○ ○ ○  │  電源軌：整條橫向相連
    － →  │ ○ ○ ○ ○ ○   ○ ○ ○ ○ ○   ○ ○ ○ ○ ○  │
          │                                           │
          │   1   2   3   4   5   6   7   8  ...      │
      a   │   ○   ○   ○   ○   ○   ○   ○   ○           │ ┐
      b   │   ○   ○   ○   ○   ○   ○   ○   ○           │ │ 同一「直行」的
      c   │   ○   ○   ○   ○   ○   ○   ○   ○           │ │ a–e 五孔相連
      d   │   ○   ○   ○   ○   ○   ○   ○   ○           │ │
      e   │   ○   ○   ○   ○   ○   ○   ○   ○           │ ┘
          │ ═══════════ 中 間 溝 ═══════════           │  溝的上下兩側不相連
      f   │   ○   ○   ○   ○   ○   ○   ○   ○           │ ┐
      g   │   ○   ○   ○   ○   ○   ○   ○   ○           │ │ f–j 五孔相連
      h   │   ○   ○   ○   ○   ○   ○   ○   ○           │ │
      i   │   ○   ○   ○   ○   ○   ○   ○   ○           │ │
      j   │   ○   ○   ○   ○   ○   ○   ○   ○           │ ┘
          │ ＋ ○ ○ ○ ○ ○   ○ ○ ○ ○ ○   ○ ○ ○ ○ ○│
          │ － ○ ○ ○ ○ ○   ○ ○ ○ ○ ○   ○ ○ ○ ○ ○│
          └───────────────────────────────────────────┘
```

三條規則：

1. **同一直行、同一側的五個孔相連。** 例如 `3a` `3b` `3c` `3d` `3e` 是同一個接點。想把兩樣東西接在一起，就插進同一直行。
2. **中間溝的上下兩側不相連。** `3a`（上半）和 `3f`（下半）是兩個獨立接點。溝的寬度剛好是 IC 晶片的腳距，所以晶片跨過去時左右腳不會短路。
3. **左右兩條電源軌（紅／藍線）是整條橫向相連的**，方向跟主區相反。用來分配 GND 和 3.3V。

⚠️ **「直行」是相對於板子本身，不是相對於你的視角。**（2026-09-14 實際踩到）

相通的那 5 個孔永遠沿著板子的**短邊**排列。板子橫著放的時候，它們看起來就是「橫排」而不是「直行」，中間溝也變成垂直的。

這很容易造成兩種錯誤：

- **零件兩隻腳插進同一組 5 孔** → 等於被導線短路，完全沒作用
- **零件和它該連的東西分在中間溝兩側** → 看起來很近，其實不相通

症狀都是「接得好好的但沒反應」。判斷方式：**沿著板子短邊數，5 個一組**；不確定就用電錶通斷檔量兩個孔。

⚠️ **830 孔的板子，電源軌常常在中間斷開。** 看紅線或藍線有沒有中斷一小段 —— 有中斷就代表左半和右半是分開的，要另外用一條短線把它們接起來，否則右半邊會沒電。這是很常見的卡關點，而且症狀是「一半能動一半不能」，不容易聯想到。

**驗證方式**：電錶通斷檔，兩支表棒插進 `1a` 和 `5a`（同行不同排）→ 應該嗶。插進 `1a` 和 `1f`（跨溝）→ 應該不嗶。電源軌左端和右端 → 嗶就是連通的，不嗶就是中間斷開。

### 杜邦線：公頭母頭

- **公頭（針）** —— 插進麵包板的孔、或插進模組的母座
- **母頭（孔）** —— 套在排針上，例如 ESP32 板子邊緣那排金屬針

所以常用的組合是：

| 從 | 到 | 要哪種線 |
| --- | --- | --- |
| ESP32 排針 | 麵包板 | **公對母**（母端套排針，公端插麵包板） |
| 麵包板 | 麵包板 | **公對公** |
| ESP32 排針 | 模組母座 | **母對母** |

套裝裡三種通常都有。如果 ESP32 已經插在麵包板上（排針插進孔裡），那所有連線都變成公對公。

### 電錶 A830L 怎麼操作

**表棒插哪裡**（這一步錯了會燒電錶）：

| 插孔 | 插什麼 | 什麼時候 |
| --- | --- | --- |
| `COM` | **黑棒，永遠插這裡** | 全部情況 |
| `VΩmA` | 紅棒 | 量電壓、電阻、通斷 —— 我們全部的操作 |
| `10ADC` | 紅棒 | 量大電流。**這個專案完全用不到** |

⚠️ **紅棒插在 `10ADC` 時，兩支表棒等於一條導線。** 這時候去碰電源正負兩端就是直接短路，會燒電錶、也可能燒變壓器。量完電流一定要把紅棒插回 `VΩmA`。這個專案不需要量電流，**紅棒就一直放在 `VΩmA` 別動**。

**檔位怎麼選**：A830L 是手動換檔，檔位上的數字是**該檔的上限**，要選比預期值大的最小一檔。

| 要量什麼 | 轉到 | 預期讀數 |
| --- | --- | --- |
| 電磁鎖線圈電阻 | `200`（歐姆區） | 約 `30` |
| 下拉電阻 10kΩ | `20k` | 約 `10.00`（單位是 kΩ） |
| LED 限流電阻 220Ω | `2000` | 約 `220` |
| 變壓器輸出電壓 | `20`（DCV 區，標示 `V⎓`） | 約 `12.0` |
| 兩點是否相連 | 蜂鳴符號 `•)))` | 相連會嗶 |

**讀數怎麼看**：

- 顯示 **`1`** 孤零零在左邊，右邊空白 → **超出量程**，代表「比這一檔的上限還大」。量電阻時就是**開路（不相連）**的意思，簡寫 `OL`。不是故障。
- 顯示 **`0`** 或 `00.0` → 幾乎沒有電阻，**兩點直接相連**。
- 電壓讀數前面有 **`-`** → 表棒接反了，把紅黑對調。

**開始前先驗電錶**：轉到蜂鳴檔，兩支表棒的金屬尖端互相碰一下 —— 應該嗶，且顯示接近 `0`。沒嗶就是電池沒裝好或表棒沒插好，先解決這個再往下。

### 螺絲端子怎麼鎖線

MOS 模組和 DC 免焊母頭用的是螺絲端子（綠色或藍色的方塊，上面有小螺絲）。

1. 電線末端剝掉約 **5–7 mm** 的外皮，露出銅芯
2. 銅芯稍微擰緊，不要有散開的細絲
3. 逆時針轉鬆螺絲，銅芯插到底，順時針鎖緊
4. **輕拉電線測試** —— 拉得出來就是沒鎖緊

⚠️ **散開的銅絲是短路的主因。** 插進去之前看一眼有沒有幾根跑到隔壁端子。這種短路用眼睛很難發現，但用電錶通斷檔量兩個端子之間就會抓到。

## 零件辨識

零件本身沒有說明書，靠外觀和電錶認。下面幾樣認錯會直接燒東西。

### LED：長腳是正極

LED 只能單向通電，接反不會亮（也不會壞）。

- **長腳 = 正極（陽極）**，接 GPIO 那一側
- **短腳 = 負極（陰極）**，接 GND
- 腳被剪過看不出長短時：看塑膠殼**側面有一個平切面**，平切面那一側是負極；或透過殼看進去，**裡面金屬片比較大的那一邊是負極**

⚠️ **LED 一定要串一顆 220Ω 電阻**，不可以直接接 3.3V。LED 本身幾乎不限流，直接接會瞬間燒掉（有時還會連帶傷到 GPIO）。電阻串在哪一側都可以，效果一樣。

### 電阻：色環怎麼讀

四環電阻，前三環是數值，第四環（金色）是誤差。讀的方向是**金色環放右邊**。

| 電阻 | 色環 | 用途 |
| --- | --- | --- |
| **220Ω** | 紅 紅 棕 金 | 串 LED 限流 |
| **10kΩ** | 棕 黑 橙 金 | MOS 觸發腳下拉 |

算法：前兩環是數字（紅=2、棕=1、黑=0），第三環是後面加幾個零（棕=1 個、橙=3 個）。所以 紅紅棕 = 22 加一個零 = 220；棕黑橙 = 10 加三個零 = 10000。

**色環顏色很容易看錯**（尤其紅/橙、棕/黑在黃光下）。**直接用電錶量最可靠**：量 220Ω 轉到 `2000` 檔（讀到約 `220`），量 10kΩ 轉到 `20k` 檔（讀到約 `10.00`）。兩支表棒碰電阻兩端，讀數就是答案。

⚠️ **檔位上的數字是該檔的上限，要選比待測值大的最小一檔。** 220Ω 若用 `200` 檔會超出量程、顯示 `1`，很容易誤判成電阻壞掉。電阻沒有方向性，怎麼碰都行。

### 四腳輕觸開關：插錯方向會永遠導通

這是最容易卡住的零件。它有四隻腳，但**其實只有兩個接點** —— 同一側的兩隻腳在內部是永遠相連的，按下去才會把兩側接通。

```
        ┌─────────┐
    1 ──┤         ├── 3        1 和 2 內部永遠相連
        │  按鈕   │            3 和 4 內部永遠相連
    2 ──┤         ├── 4        按下時，左側和右側接通
        └─────────┘
```

如果插麵包板時方向轉了 90 度，你用到的兩隻腳剛好是「永遠相連」的那一對，**電路會表現得像按鈕一直被按著**，而且看起來完全正常，非常難查。

**正確做法**：插的時候讓**同一側的兩隻腳落在同一直行裡**。這樣那一直行整個是「一側」，另一直行是「另一側」，兩行之間只有按下才通。

⚠️ 常見的錯誤建議是「跨過中間溝插」。跨溝的確能保證做對，但**不是唯一方法，而且很多開關跨不過去** —— 中間溝寬 7.62mm，6×6 開關的腳距只有 4.5×6.5mm，構不到。整顆插在同一半完全可行，只要方向對。

方向錯的症狀很有辨識度：**每一直行會同時拿到左右兩側各一隻腳，兩行被內部永遠連通，按鈕表現得像一直被按著**，而且外觀完全正常。解法就是轉 90 度重插。

**保險做法（建議第一次這樣做）**：拿電錶通斷檔量四隻腳的 6 種組合，會找到 **2 組「不按就嗶」**（同側，不能同時用）和 **4 組「按下才嗶」**（不同側，用這種）。

**插好之後的最終驗證**（這一項通過就一定對，不必管開關規格）：蜂鳴檔，一棒碰訊號線那一行的空孔、一棒碰 GND 那一行 —— **不按不嗶、按下才嗶**。

### 1N4007 二極體：銀環是陰極

黑色小圓柱，身上印一圈**銀色或白色的環**，**有環的那一端是陰極**。

接的方向見「步驟四」。**這一顆接反會直接短路 12V 電源**，是整個電路裡後果最嚴重的單一錯誤。

**電錶驗證（順便確認二極體是好的）**：轉到蜂鳴／二極體檔，紅棒碰無環端、黑棒碰有環端 → 應顯示約 `0.5` 到 `0.7`（這是順向壓降，不是電阻）。表棒對調 → 應顯示 `1`（不導通）。兩個方向都導通或都不導通，這顆是壞的，換一顆。

### MOS 模組：先認端子再接線

模組上的絲印每家不同，不要憑字面猜。辨識方法見「步驟二」，那是用電錶確認的，比讀字可靠。

### ESP32 排針：對照絲印，不要數腳位

板子邊緣每一支針旁邊都印了名稱（`4`、`5`、`GPIO4`、`IO4` 等寫法都有）。**一律看絲印**，不要從板子角落開始數 —— 不同廠商的排列順序不一樣，數錯一位就接到別支腳。

絲印太小看不清楚時用手機拍照放大。找不到需要的腳位就先停，拍照給我看板子兩面。

## 本機這塊 C3 核心板的實際腳位（2026-09-14 實測確認）

板子是**合宙 LuatOS ESP32-C3 核心板**，21×51mm，已焊排針。

## 腳位辨識工具

數腳位不可靠時，用 `firmware/pin-finder/` 這支診斷韌體，不必數。

原理是讓每支目標腳位用不同的開關比例快速閃爍（250Hz）。電錶直流電壓檔量到的是平均值，所以每支腳會讀到不同電壓 —— 等於一張用電錶就能讀的「身分證」。

```bash
cd firmware/pin-finder && pio run -e esp32-c3 -t upload
```

燒好後 USB 不要拔，電錶轉 DCV `20` 檔，黑棒碰 USB 金屬外殼，紅棒依序碰每支針：

| 讀到 | 是哪支 |
| --- | --- |
| 約 3.3V | IO7 |
| 約 2.5V | IO6 |
| 約 1.7V | IO4 |
| 約 0.8V | IO5 |
| 約 0.0V | IO0/1/2/3/10（對照組） |
| 跳動不穩 | 其他腳位，程式沒碰 |

**更快的用法**：IO7 在這支程式裡是 100% 恆定高電位，所以把 LED 那條線插到 IO7，**燈會恆亮**。一個動作就同時驗證了線、母頭、麵包板直行、LED 方向、電阻、GND 迴路六件事，連電錶都不用拿。

用完記得燒回正式韌體。

## 模擬接線（不用鎖、不用 12V）

鎖還沒到就可以做這一段。**全程只有 3.3V，接錯最多是不會動，不會燒東西。**

### 要接什麼

鎖在電路上只是兩樣東西，各用一個零件代替：

| 真實零件 | 用什麼代替 | 接哪 |
| --- | --- | --- |
| 電磁鎖線圈 | **LED + 220Ω 電阻** | GPIO4（亮 = 通電） |
| 鎖舌回饋接點 | **輕觸開關** | GPIO5（按下 = 鎖舌縮回） |
| —— | 另一顆 LED + 220Ω | GPIO7（心跳燈） |

### ESP32 怎麼放

**優先讓板子跨過麵包板的中間溝插下去** —— 這樣每一支腳各自佔一個五孔group，旁邊還有孔可以插線。

⚠️ **C3 核心板寬 21 mm，不一定剛好對上麵包板 2.54 mm 的孔距。** 插不進去就不要硬壓，改用**公對母杜邦線**直接套在板子的排針上，另一端插麵包板。效果完全一樣，只是桌面亂一點。

### 連線清單

`GND` 先用一條線拉到麵包板的負電源軌（藍線那條），之後所有接地都從那條軌取用 —— 這樣不用在 ESP32 上擠好幾條線。

| # | 從 | 到 |
| --- | --- | --- |
| 1 | ESP32 `GND` | 麵包板 負電源軌（藍） |
| 2 | ESP32 `GPIO4` | LED-A 長腳（正極） |
| 3 | LED-A 短腳（負極） | 220Ω 電阻一端 |
| 4 | 220Ω 另一端 | 負電源軌 |
| 5 | ESP32 `GPIO5` | 輕觸開關 一側任一腳 |
| 6 | 輕觸開關 另一側任一腳 | 負電源軌 |
| 7 | ESP32 `GPIO7` | LED-B 長腳 → 220Ω → 負電源軌（同 2–4） |

WROOM 板子的話，`GPIO4`→`GPIO26`、`GPIO5`→`GPIO27`、`GPIO7`→`GPIO25`。

**按鈕為什麼只接 GPIO 和 GND，不用接 3.3V**：韌體把這支腳設成 `INPUT_PULLUP`，晶片內部已經有一顆電阻把它拉到 3.3V。沒按時讀到 HIGH，按下接到 GND 讀到 LOW。所以邏輯是反的 —— **LOW 才代表「按下」**。

**按鈕方向記得驗**：見「零件辨識」那一節，插錯 90 度會表現得像一直被按著。

### 怎麼判斷成功

燒錄後開監看（`pio device monitor -b 115200`），應該看到：

| 觀察 | 正確結果 | 不對的話 |
| --- | --- | --- |
| GPIO7 的 LED | 每 0.5 秒閃一次 | 不閃 → LED 接反，或電阻沒接上 |
| 開機訊息 | 印出一次 `[回饋] 接點開路（鎖舌伸出）` | 反覆刷屏 → 按鈕方向錯，插成永遠導通那一對 |
| 按下按鈕 | 印出 `接點閉合（鎖舌縮回）`，GPIO4 的 LED 亮 | 沒反應 → 按鈕那兩腳是同一側的，換一腳 |
| 放開按鈕 | 印出 `接點開路`，LED 熄 | —— |

**這四項都對，代表韌體邏輯是正確的。** 之後真鎖接上去若出問題，就確定是接線問題，不用再懷疑程式。這正是先做模擬的目的。

### 疑難排解：開機迴圈（2026-09-14 實際遇到）

**症狀**：燒錄顯示成功，但序列埠不斷重複下面這段，看不到程式的輸出：

```
ESP-ROM:esp32c3-api1-20210207
rst:0x3 (RTC_SW_SYS_RST),boot:0xc (SPI_FAST_FLASH_BOOT)
Saved PC:0x403cf94c
```

關鍵特徵是 **ROM 交棒之後什麼都沒印就重置了** —— 連第二階段 bootloader 的訊息都沒有。這代表問題發生在程式跑起來之前，**不是程式邏輯的問題**，改程式沒有用。

**原因**：這塊板子的 flash 是 Boya（博雅，製造商代碼 `0x68`），不是原廠常用的 GD／Winbond。PlatformIO 的 `esp32-c3-devkitm-1` 板子定義預設用 **QIO** 模式讀 flash，而 QIO 的啟用方式各家不同，bootloader 切換失敗就直接重置。

**修法**：在 `platformio.ini` 的 C3 環境裡覆寫成 DIO。

```ini
board_build.flash_mode = dio
```

已經寫進 `firmware/smart-bin/platformio.ini`。代價是讀取略慢，對這個專案沒有影響。

**怎麼查自己板子的 flash 是哪家**：

```bash
/usr/local/Cellar/platformio/6.2.0/libexec/bin/python \
  ~/.platformio/packages/tool-esptoolpy/esptool.py \
  --port /dev/cu.usbmodem5B7A1236081 flash_id
```

輸出的 `Manufacturer:` 就是製造商代碼。順便會印出晶片版本（本機這塊是 **ESP32-C3 revision v0.4**）和 flash 容量（4MB）。

⚠️ 要用 PlatformIO 自帶的 python 跑 —— 系統的 python3 沒有裝 `pyserial`，直接跑 `esptool.py` 會報 `No module named 'serial'`。

## 兩個電壓域

這個電路裡有兩種電壓，**它們只有一個地方可以相接**：

```
12V 域                          3.3V 域
─────────────────────────       ─────────────────────────
變壓器 → DC 母頭                 ESP32-C3（USB 或 3V3 腳供電）
       → MOS 模組電源輸入        → MOS 模組觸發腳
       → 電磁鎖線圈              → 電磁鎖回饋接點（乾接點，不帶電）
       → 1N4007

                    ↓ 唯一交會點 ↓
                   共地（GND 相接）
```

**共地是必須的。** MOS 模組靠「觸發腳相對於 GND 的電壓」判斷開關，如果 ESP32 的 GND 和 12V 電源的負極沒有相接，兩邊沒有共同參考點，觸發訊號的電壓就沒有意義，模組會亂動或完全不動。這是初學者接 MOS 最常見的失敗原因。

**除了共地以外，12V 的任何一條線都不可以碰到 ESP32。** ESP32-C3 的 GPIO 耐壓是 3.3V，12V 進去就是永久損壞，而且通常連帶燒掉 USB 端。

## 步驟一：辨識電磁鎖的四條線

**在接任何東西之前做這一步。** 四線鎖裡有兩條是 12V 線圈、兩條是回饋接點，接錯會把 12V 灌進 GPIO。線的顏色各家不同，**不要憑顏色猜**。

電錶轉到 **200Ω** 檔（不要用蜂鳴通斷檔——線圈約 30Ω，剛好在 A830L 蜂鳴門檻附近，可能響也可能不響，讀數才可靠）。

鎖不接電，四條線兩兩量，共 6 組組合：

| 讀數 | 代表 |
| --- | --- |
| **約 25–40Ω** | 線圈。額定 12V / 0.4A ⇒ 12 ÷ 0.4 = 30Ω，實測落在這個範圍就對了 |
| **0Ω 或 OL（開路）** | 回饋乾接點。哪一種取決於現在鎖舌伸出還是縮回 |
| **OL** | 線圈與回饋之間的所有交叉組合 |

最後一列是安全檢查，不是可有可無的：**線圈任一條對回饋任一條若不是 OL，就停下來。** 那表示回饋不是獨立的乾接點，接到 GPIO 會把 12V 帶進去。

記錄結果（貼標籤或拍照）：

```
線圈 A ＿＿＿色    線圈 B ＿＿＿色
回饋 A ＿＿＿色    回饋 B ＿＿＿色
```

回饋是哪一組要到步驟五通電後才能最終確認——那時鎖舌會動，回饋讀數會跟著變。

## 步驟二：辨識 MOS 模組的端子

模組上的絲印標示各家不同，用電錶確認比讀字可靠。不接任何電，通斷檔（蜂鳴）測：

| 測量 | 應該 | 說明 |
| --- | --- | --- |
| 電源輸入 `+` ↔ 輸出 `+` | **導通（嗶）** | 這類模組是低邊開關：正極直通，被切斷的是負極 |
| 觸發端 GND ↔ 電源輸入 `−` | **導通（嗶）** | 觸發訊號與負載電源共用同一個地 |
| 電源輸入 `−` ↔ 輸出 `−` | **不導通** | 這就是 MOS 切斷的地方 |

三項都符合，就確定了整塊板子的拓撲，即使絲印看不懂也不影響。

還有一項：**觸發腳 ↔ GND 的電阻**（`20k` 檔）。

- 讀到 **10kΩ 上下** → 板上有內建下拉電阻，很好
- 讀到 **OL** → 觸發腳是浮空的，**必須自己加一顆 10kΩ 電阻**從觸發腳接到 GND

為什麼要在意：ESP32 重開機的瞬間，GPIO 會有一小段時間是浮空輸入，不驅動任何電壓。觸發腳如果也浮空，電壓不確定，**MOS 可能在開機瞬間自己導通，鎖就無故打開了**。下拉電阻確保「沒有明確訊號時 = 關」。

套裝裡應該有電阻包，找 棕-黑-橙-金（10kΩ）。

## 步驟三：接線表

以 ESP32-C3 為主平台，WROOM-32 附對照腳位（同一份韌體要能在兩塊板上跑，開發時 WROOM 比較好插麵包板）。

### 訊號線

| 功能 | C3 腳位 | WROOM 腳位 | 接到 | 模式 |
| --- | --- | --- | --- | --- |
| 開鎖控制 | **GPIO4** | GPIO26 | MOS 模組 觸發腳 | `OUTPUT`，開機預設 `LOW` |
| 鎖舌回饋 | **GPIO5** | GPIO27 | 電磁鎖 回饋 A | `INPUT_PULLUP` |
| 測試按鈕 | **GPIO6** | GPIO33 | 套裝按鈕一腳 | `INPUT_PULLUP` |
| 狀態 LED | **GPIO7** | GPIO25 | LED 正極（串 220Ω 到 GND） | `OUTPUT` |
| — | GND | GND | 電磁鎖 回饋 B、按鈕另一腳、MOS 觸發 GND | — |

腳位不是隨便挑的：

- **C3 避開 GPIO2 / 8 / 9**，這三支是 strapping 腳，開機瞬間的電位會影響啟動模式（GPIO9 還是 BOOT 鍵）。掛負載在上面會導致有時候開不了機，而且症狀是間歇性的，非常難查。
- **C3 避開 GPIO18 / 19 / 20 / 21**，分別是 USB 和序列埠，佔用了就沒法看 log。
- **WROOM 避開 GPIO34–39**：那些是唯讀腳，**沒有內部上拉電阻**。回饋接點靠 `INPUT_PULLUP` 才能讀，接在那裡會永遠讀到浮空亂值。
- **WROOM 避開 GPIO6–11**（接快閃記憶體）與 GPIO0 / 2 / 12 / 15（strapping）。

回饋接點是乾接點，兩端沒有極性，A / B 對調沒關係。`INPUT_PULLUP` 讓腳位平常被拉到 3.3V（讀 `HIGH`），接點閉合時被拉到 GND（讀 `LOW`）。哪個狀態對應「鎖舌伸出」要在**步驟六 A 段**通電時實測，不要猜。

### 從模擬接線改成真鎖，要動哪幾條

模擬階段（LED + 按鈕）跑通之後，**訊號線只換兩處，其餘不動**：

| 原本 | 換成 |
| --- | --- |
| GPIO4 → LED-A 長腳 | GPIO4 → **MOS 模組的觸發腳** |
| GPIO5 → 輕觸開關 | GPIO5 → **電磁鎖 回饋 A** |
| 負電源軌 ← LED-A 的 220Ω | 拆掉（LED-A 和它的電阻整組移除） |
| 負電源軌 ← 輕觸開關另一腳 | 負電源軌 ← **電磁鎖 回饋 B** |

GPIO7 的心跳燈保留，它是判斷程式有沒有卡死的依據，之後每一步都用得到。

**韌體一行都不用改。** 對 ESP32 來說，「LED 亮」和「MOS 導通」是同一件事（GPIO 輸出高電位），「按鈕按下」和「回饋接點閉合」也是同一件事（GPIO 被拉到 GND）。這就是模擬階段能驗證邏輯的原因。

另外要新接的是 12V 那一側，見下。**負電源軌這時候會同時連到 ESP32 的 GND 和 12V 電源的負極** —— 那就是「共地」，是刻意的，也是唯一允許兩個電壓域相接的地方。

### 電源線（12V）

```
變壓器 ──→ DC 母頭 ┬── (+) ──→ MOS 電源輸入 +
                    └── (−) ──→ MOS 電源輸入 −

MOS 輸出 + ──→ 電磁鎖 線圈 A
MOS 輸出 − ──→ 電磁鎖 線圈 B

1N4007 跨接在線圈兩端：
    銀色環那一端（陰極）──→ 線圈 A（接 MOS 輸出 + 那側）
    另一端（陽極）      ──→ 線圈 B（接 MOS 輸出 − 那側）

ESP32 GND ──→ DC 母頭 (−)     ← 共地，唯一的交會點
```

**DC 母頭極性：內正外負。** 中間那根針是 +12V，外圈是負。母頭上通常有紅黑分色或 +／− 標示，但**一定要用電錶量過**：電壓 DC 20V 檔，紅棒碰接出來的正極線，黑棒碰負極線，讀到 **+12V 左右**才對。讀到 −12V 就是接反了。

## 步驟四：1N4007 的方向

**這一顆接反會直接短路 12V 電源。**

二極體只讓電流單向通過。正常工作時（線圈 A 是 +12V，線圈 B 被 MOS 拉到 GND），二極體是逆向的，不導通，等於不存在。

MOS 關斷的瞬間，線圈的電感會試圖維持電流，讓線圈 B 那一端的電壓**衝到 12V 以上**（幾十甚至上百伏）。這時二極體變成順向，把這股能量導回去消耗掉。沒有它，這個突波會打穿 MOS——這是電感負載最典型的故障。

接反的話，二極體從一開始就順向導通，等於用一根導線把 12V 正負極接在一起。

**辨識方法：二極體本體上印一圈銀色（或白色）環，有環的那一端是陰極。陰極朝 +12V。**

位置盡量靠近鎖，讓突波的迴路面積小。

## 步驟五：通電前檢查清單

接完線、**還沒插電**時，逐項確認。每一項都是為了防止一種具體的損壞：

1. **12V 短路檢查** — 電錶 200Ω 檔，量 DC 母頭的正負兩端。應讀到**線圈的 30Ω 左右**（透過 MOS 正極直通與二極體）。若讀到 **0Ω 或個位數，停止**，某處短路了。
2. **極性檢查** — 變壓器單獨插電（先不接電路），電錶 DC 20V 檔量 DC 母頭輸出，確認 **+12V**、正負沒反。量完拔掉再接電路。
3. **共地檢查** — 通斷檔，ESP32 的 GND ↔ DC 母頭負極，應**導通**。
4. **隔離檢查** — 通斷檔，ESP32 的 **3V3 腳 ↔ DC 母頭正極**，必須 **OL（不導通）**。有嗶聲代表兩個電壓域接在一起了，插電就燒板。
5. **二極體方向** — 目視，銀環朝 +12V 側。
6. **觸發腳下拉** — `20k` 檔，MOS 觸發腳 ↔ GND，應讀到約 `10.00`（即 10kΩ，內建或自己加的）。

**電錶注意：不要用電流檔去量電源兩端。** A830L 的 10A 插孔內阻極低且無保險絲，直接跨在電源上等於短路，會燒電錶也可能燒變壓器。電流檔只能串聯在迴路中。

## 步驟六：分段上電

不要一次全接好通電。每一段只驗證一件事，出問題才知道是哪裡。

**A 段——只有鎖和電源。** 不接 MOS、不接 ESP32。變壓器 → DC 母頭 → 直接短暫碰觸線圈兩端（1 秒內）。應聽到「喀」一聲、鎖舌縮回。放開後鎖舌彈出。

同時：電錶量回饋接點那一組，**在鎖舌縮回與伸出時讀數應該改變**（0Ω ↔ OL）。這一步同時確認了鎖是好的、極性可用、回饋接點有效，並且記下哪個狀態對應哪個位置。

✅ **這顆鎖可以連續通電**（2026-09-18 實測）。商品頁標示連續通電時間 < 24 小時；實際通電 60 秒後鎖體幾乎無感，與 12V × 0.4A = 4.8W 的發熱量相符。

原先假設它是短時工作制（≤10 秒），並據此推論「投放窗 30 秒與線圈上限衝突」。**該推論不成立**，是基於未經查證的假設。

⚠️ 但這個結論**只適用於這顆鎖**。換成陽極鎖或電插鎖等短時工作制的型號時，必須回頭改 `LOCK_MAX_ENERGISE_MS`，否則會燒線圈。

⚠️ 另外，實測是在通風的桌面上做的。垃圾桶是封閉外殼，夏天曝曬的散熱條件完全不同，外殼定案後應重測一次。

**B 段——加上 MOS，手動觸發。** 接好 12V 側與二極體，先不接 ESP32。用一條杜邦線把 MOS 觸發腳短暫接到 3.3V（可用 ESP32 的 3V3 腳供電但不接 GPIO），鎖應該動；接到 GND，鎖應該停。這一步驗證 MOS 與二極體接對了。

**C 段——接上 ESP32 跑韌體。** 到這裡所有硬體都已經個別驗證過，剩下的問題就都在程式裡。

## 對韌體的硬體約束

接線方式決定了幾件韌體必須遵守的事，寫在這裡免得日後重新推導：

- **開機時 GPIO4（C3）必須先設為 `OUTPUT` 且 `LOW`，再做其他初始化。** 配合硬體下拉，確保開機過程中鎖不會誤開。
- **通電時間必須有上限。** 依鎖的短時工作制規格設一個硬上限（暫定 10 秒，待查證），無論狀態機處在哪一步，超時一律斷電。這是保護硬體，不是產品邏輯。
- **開鎖流程是「通電 → 等回饋確認鎖舌縮回 → 等蓋子開啟或逾時 → 斷電」。** 斜舌設計讓蓋子關上時能把鎖舌壓回去自動上鎖，所以不需要反向驅動。
- **用鎖舌的第二次縮回判斷蓋子已闔上（2026-09-18 定案）。**

  不加蓋子感測器。理由是鎖舌只有在**不處於鎖孔裡**的狀態下才會被關門時的斜面壓回去；蓋子從未開過的話鎖舌一直在孔裡，沒有東西能壓它。所以第二次縮回同時證明了兩件事：蓋子曾經開過，而且正在關上。事件鏈因此從四段收斂為三段：

  ```text
  unlock_confirmed → hatch_closed → latch_locked
  ```

  `hatch_opened` 不再是獨立事件，而是由 `hatch_closed` 邏輯上隱含。

  **代價**：分不出「蓋子卡住沒開」與「開著但人走了」，兩者都是沒有第二次縮回，只能一起逾時處理。兩種都不是成功投放，後端處理方式相同。

  **已知破口**：有人用手指把鎖舌壓回去可以偽造「蓋子關上了」。不在威脅模型內 —— HMAC 與計數器防的是「App 遠端自稱完成」這種可規模化的攻擊；跑到垃圾桶前壓鎖舌，還不如直接投一包東西進去。

  **時序驗證**（2026-09-18，以按鈕模擬關蓋動作，六次）：壓回時長 135／164／165／169／174／182 ms，最短為防彈跳 30 ms 的 4.5 倍。真蓋子有重量與行程，關閉比手按更慢，因此這組數字是保守下限。防彈跳不需調整。

- **開鎖必須是脈衝，不能持續通電（2026-09-18 定案）。**

  早期版本在鎖舌確認縮回後持續通電到投放窗結束。那是錯的：斜舌要彈出來卡進鎖孔才叫上鎖，而線圈通電期間鎖舌被拉住縮回 —— **持續通電會主動阻止蓋子上鎖**。使用者 10 秒投完，卻得按著蓋子等到 30 秒斷電才能真正關上，既浪費時間也浪費電。

  改為：通電 → 等鎖舌縮回 → 續電 `PULSE_HOLD_AFTER_RETRACT_MS` 讓蓋子彈開並使鎖舌脫離鎖孔 → 斷電。之後任何時候關上蓋子，斜舌都會自動卡上。

  `window_seconds` 的意義隨之改變：從「通電多久」變成「多久沒關上就視為未完成」。協定欄位未動，語意已改，JSON 定義書須同步。

  ⚠️ `PULSE_HOLD_AFTER_RETRACT_MS` 目前為 400 ms，是估計值。太短則鎖舌在蓋子讓開前就彈回鎖孔，等於沒開。實際值要等蓋子機構做好才能定 —— 彈簧力道與鉸鏈阻力都會影響。

- **回饋接點要做防彈跳，但別把接觸不良誤當成彈跳（2026-09-14 實測）。**

  同一顆輕觸開關、同一份韌體，量到兩組差很多的數字：

  | 情況 | 按 3～5 下的狀態變化次數 |
  | --- | --- |
  | 有零件沒插到底（腳被折彎，卡在孔口） | **343 次** |
  | 把零件腳拉直、確實插進夾片後 | **3 次**（按幾下就幾次） |

  我一開始把 343 次判斷成機械彈跳，是錯的。真正的原因是接觸不良造成的斷續通斷 —— 修好接線之後彈跳幾乎量不到。

  兩者的處理方式相反：**彈跳是開關的物理特性，只能在軟體吸收；接觸不良是接線缺陷，要修好而不是用軟體蓋掉。** 若一開始就加了寬鬆的防彈跳，這個接線問題會被藏起來，之後在真鎖上以更難查的形式再出現。

  由此得到一個有用的判準：**狀態變化次數異常暴增，本身就是接觸不良的徵兆**，先查接線再談濾波。

  正式韌體仍應實作防彈跳（真實開關確實會彈跳，只是量級遠小於此），建議 20–50 ms，並且**把異常高的變化次數記錄下來當作硬體健康指標**。

- **回饋沒有在預期時間內變化 ⇒ `lock_failed`**，對應 SMART_BIN_DESIGN.md 的錯誤碼表。這正是回饋接點存在的理由：沒有它，裝置無法區分「鎖打開了」和「輸出了訊號但鎖卡住」，而回執只有在能區分時才值得後端相信。

## 這一階段之後還缺的零件

第一階段 ESP32 靠 USB 供電（接電腦或行動電源），所以現在不缺。但要讓垃圾桶獨立運作時會缺一樣：

**12V 轉 5V 的降壓模組**（例如 LM2596 可調降壓板，約 NT$30–50）。

⚠️ **絕對不可以把 12V 直接接到 ESP32 的 `5V` 或 `VIN` 腳。** C3 核心板的輸入上限通常是 5V，12V 進去會燒穩壓器，常常連帶燒掉整塊板。

這一項等第一階段跑通再買，現在不用急。
